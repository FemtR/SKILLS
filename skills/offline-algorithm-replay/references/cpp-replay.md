# C/C++ 独立回放入口

## 最小可运行边界

找到正式公开接口或内部模块入口，确认所需源文件、库、宏、编译模式和数据类型。优先创建独立测试可执行文件，而非为了回放修改 GUI 启动流程。

通常可以替换日志和绘图回调；定位可能还需要地图、匹配库和外参，完整 SLAM 还需要模式配置、轮速、IMU、时间戳及状态同步。依据当前实现决定依赖，不把某个 detector 的轻量依赖推广到整个管线。

日志替身不应改变算法状态。计算替身需要额外对照，例如二维相对位姿必须包含前一姿态下的平移变换，不能只减 x/y 并忽略旋转。

## 事件驱动

```cpp
for (const auto& capture : captures) {
    auto algorithm = CreateProductionAlgorithm(capture.configuration);
    for (const auto& event : capture.events) {
        DispatchProductionEvent(*algorithm, event);
    }
    CollectResult(*algorithm);
}
```

这是调用结构示例，函数名是占位说明，不是现成实现。`DispatchProductionEvent` 应映射实际接口：采样输入、非采样输入、模式切换、重置或位姿同步；不要只将有点云的记录当作全部事件。结束接口可能冻结状态，不应在逐帧读取进度时反复调用。

对仅有两个坐标值的夹具可以手工构建输入；对大量真实点云，使用可追溯的二进制或结构化夹具。保留原始文件与转换后夹具的标识，避免把浮点文本舍入误差误认为算法改变。

## 构建和运行

- MSVC：查找安装的工具链，在匹配位数的开发环境中构建。使用与正式模块相同的宏和必要编译选项，记录是否启用断言。
- CMake：优先复用已有库目标，只添加需要的回放入口；数据集通过参数或清单传入，不硬编码某台电脑的目录。
- 动态库：核实载入路径与文件哈希。重新生成 DLL 不代表测试可执行文件载入了它。
- 断言测试不能在定义 NDEBUG 后静默失效；使用显式失败返回或确认断言已启用。
- 用输入尺寸、帧数量和实际判定输出确认回放确实执行，不能只依赖退出码为零。

若项目构建目标会关闭应用、复制库或启动 GUI，用已有开关禁用这些步骤，或在独立构建目录编译回放程序；不要为无界面测试自动增加部署操作。

## 验证分级

1. 数值复算对照：帮助确认解析、单位和特征，但未验证正式算法实现。
2. 实际模块对照：验证正式模块在固定输入下的行为；列明替换的依赖和旧日志状态。
3. 完整算法回放：当前代码生成定位、建图和下游状态；仍不包含 GUI、真实设备或调度验证。
4. 应用运行对照：验证加载、界面与生命周期，并与回放指标核对。

选择能回答用户问题的最小层级，遇到依赖范围变化时再升级，不把最高层级强加给每次局部修复。
