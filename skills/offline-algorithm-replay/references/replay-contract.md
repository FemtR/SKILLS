# 回放契约

按项目实际接口记录下列内容，避免为简单单函数测试建立不必要的框架。

## 输入契约

| 项目 | 需要核对的内容 |
|---|---|
| 记录结构 | 标记、版本、长度、字节序、压缩和字段类型 |
| 帧关联 | 记录顺序、一次采集中重置的帧号、缺失记录 |
| 数值 | 距离、角度、时间单位，浮点精度 |
| 坐标 | 世界、机器人、传感器坐标；外参和相对变换方向 |
| 预处理 | 距离裁剪、降采样、扫描补偿、点云合并的执行位置 |
| 生命周期 | 开始、模式变化、位姿同步、重置、结束 |
| 状态来源 | 原始传感器输入、新算法生成、旧日志决策、测试替身 |

二进制解析器不要遇到长度异常就无说明地跳到下一个标记。按现有格式处理或明确报告无法解析的记录；载荷中的标记可能不是记录起点。

日志文本中的字段可能缺失、截断或重复。先核实界面是否重复导出同一帧；没有确认前，不能仅凭内容相同而删除两个真实输入帧。

## 最小结果记录

以下是报告结构示例，不要求所有算法采用同一序列化格式：

```json
{
  "case_id": "capture-a",
  "scope": "stateful-module",
  "input_identity": "sha256:<hash>",
  "implementation_identity": "source-or-library-hash",
  "configuration": "configuration-identity",
  "upstream_state_source": "recorded-decisions",
  "substituted_dependencies": ["logger"],
  "expected": "NORMAL",
  "actual": "NORMAL",
  "evidence_status": "evaluated",
  "metrics": {},
  "windows": []
}
```

`evidence_status` 用于解释“正常”是否来自有效评估，或只是未采满、窗口无效、尚未执行。标签来自用户或参考依据，不能由待测算法自己生成。

## 比较策略

- 重构检查：在相同输入、配置和生命周期下对比输出；浮点容差与业务精度相关，不能为了消除差异不断放宽。
- 缺陷修复：保留能复现原问题的采集与边界；加入原先正确的样本，而非只测试新的正例。
- 阈值试验：检查误报、漏报及距离阈值的余量。若阈值来自当前样本，应明确标为样本内结果。
- 管线验证：重放原始输入并重新生成上游状态。借用旧定位或旧建图许可的模块回放不能验证这些模块的改变。
- 无真值：可检查不变量、与参考版本的差异和一致性；不能仅凭结果稳定就声称有图、定位正确或地图准确。
